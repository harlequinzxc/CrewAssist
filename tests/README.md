# CrewAssist behaviour tests

A small jsdom suite that boots the **real `index.html`** in a fake browser and drives it the way a person would: tapping buttons, typing into fields, answering dialogs, faking flight fetches. No build step, no browser, no network. Runs in ~25 seconds.

## Run it

```bash
cd tests
npm install        # once; installs the pinned jsdom (see package.json)
npm test           # or: node run-all.js
```

`node_modules/` and the lockfile are git-ignored (repo convention) — the pinned version lives in `tests/package.json`. If jsdom ever needs bumping, bump it deliberately and re-run everything.

## Conventions (what keeps this evergreen)

1. **Assert outcomes, not internals.** "The share panel received the file", not "function X called function Y". Outcome tests survive refactors — the export logic was rewritten twice without touching these assertions.
2. **New features bring their test block.** The feature's "verify" step becomes a permanent suite block, added in the same sitting as the feature.
3. **Intentional behaviour changes update the matching block.** A failing test after a deliberate spec change is the net doing its job — re-sign the contract in the same commit. The cost stays proportional: minutes, never a rewrite.
4. **IDs are contracts.** The app's element ids (`btn-dev-save`, `ca-arch-trash`, …) are stable and pinned by the owner's specs; tests may rely on them. classNames only where the spec pins them (colours, pill styling).
5. **Date-anchored seeds.** Suites that depend on "today" (current-month expansion, partial-month projections, month badges) seed the real current calendar month and **compute date-derived expectations from the run date** — never hardcode the day. A calendar rollover fails them loudly on purpose: reseed the months and figures, never change app behaviour to match stale seeds. Two traps hotfix 9 added to this rule: seeds compared against a ROLLING window (the backup nudge's "newer than the last export") must derive from the run date, not fixed ones — a fixed date crosses the window overnight; and seeds built from bare `hh:mm` strings must carry the true `ymd`/`staYmd` of real moments — near midnight the strings straddle the day boundary and trip the app's overnight-arrival rule (a 02:17 SGT run caught both). The harness pins the box to Asia/Singapore (`process.env.TZ` at require time) because the app's naive wall math (expiry sweeps, day labels) and its zone-aware station math agree only on the crew's own clock — an unpinned box can split them (the 2026-10-03 UTC sandbox did, and exposed a real on-device date bug); the pin is why.
6. **Timing:** the harness boots jsdom and waits 400ms — jsdom fires its own `DOMContentLoaded` exactly once. **Never dispatch it manually**; double-firing double-binds every listener (a real bug this suite caught). Dialog close fades take 200ms — wait ≥400ms after OK/Cancel before asserting `hidden`.

8. **`w.eval` sees function declarations, not `let` bindings.** Top-level `let`/`const` in the app's scripts never become window properties — assert through functions (`rcTintKind(...)`, `rosterCalSelect(...)`) or the DOM, never by eval-ing a variable name (hotfix 10's first heal pin died on `rcTL is not defined`).
9. **Store-shape tests boot FRESH; shared-page mutations need the re-read trio.** The calendar caches legs per dkey (`rcLegCache`) and a same-day re-select is a render no-op — so mutating `localStorage` on a page that already rendered serves STALE legs and never re-renders the detail. For a store-shape pin (duty days without flights, a store-era gap), boot a new page (`await boot(APP, { seed })`) so the store is the only voice. If you must mutate a live page (the SN60 idiom), the trio is: raw `setItem` → `rosterCalTimelineInit()` → select a DIFFERENT day and back. And run suites directly (`node suite.test.js` from `tests/`) — `_harness.js` is a library; executing it does nothing. (v1.45.50 lessons, both paid for: the first era pin ran on the shared legend page and read cached legs from earlier blocks; the solo run "passed" with empty output.)
10. **A sabotage must be able to evict the row.**
12. **Metric pins verify against hand-computed values, and new CSS rides the ladder.** A stats feature's live pins seed a small store whose every total is computed BY HAND first (the two-year telemetry seed: 9 legs / 1d 16h / KUL ×2 / 388 · 4 …) — a wrong number in the app then fails loudly against arithmetic, not against another render. And the dev-ui type-ladder guard is part of the net: new components using off-rung sizes (9px, 10px, the banned 15px) fail the battery — pick rungs (11 micro / 14 / 20 / 24), don't invent sizes.
13. **Overlay-over-overlay pins follow the stack.** When a sheet opens above another sheet (v1.45.53's All Flight Stats over the passport), the pins name BOTH wraps and their z-order, the close-of-parent also closes the child, and the Escape closers list is asserted in STACK ORDER — the top sheet's entry sits above the page beneath it. A gate that opens an overlay is pinned by its opener call, never by accordion markup that no longer exists.

14. **Re-skins re-pin the SKIN, not just the markup.** When a surface changes clothes (v1.45.54's earnings re-skin), every computed-style pin on the old look is a failing pin: grep the suite for the retired values (the navy gradient, the gold numerals, the glider transform, the mono stack, the wash alphas) and re-point each to the new idiom — then ADD pins for the new vocabulary (the pair values, both themes) so the next drift trips a wire.

15. **Ladder surgery shifts EVERY rung below the insert — walk the whole ladder after.** When a release takes entries[0] of the E6 changelog ladder, every older rung's index moves down one. A partial shift (a range loop from n≥3 plus a separate text re-point for one rung) leaves a rung unshifted or duplicated beside the new head — v1.45.55 paid for it: the 1.45.52 rung stayed at [2] next to the re-pointed 1.45.53 and the suite failed 794/1. After ANY ladder edit, print every rung's version-versus-index ([0] newest … down to the floor) before running, and let the per-rung version pins be the net that catches what the eye missed.

11. **Instant-behaviour pins read SYNCHRONOUSLY; absence pins quote the code form.** A "hides the moment the tap lands" claim is pinned by reading state in the SAME task as the click (`tagBtn.click(); R.ok(...)` with no `await wait` between) — any sleep can mask a replay window the old code left. And when a rename retires a UI string, pin the absence of its CODE forms (`aria-label="Your records"`, `>Your records</h3>`), never the bare phrase — the changelog pointer that announces the rename quotes it (the ek lesson, paid twice now: v1.45.49's comment, v1.45.51's pointer). The virtualized window renders ±6 rows of context, so scrolling a today near the timeline's start to the TOP cannot push its row out of the DOM — fling to the far bottom instead (hotfix 10).
