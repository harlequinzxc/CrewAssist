# CrewAssist behaviour tests

A small jsdom suite that boots the **real `index.html`** in a fake browser and drives it the way a person would: tapping buttons, typing into fields, answering dialogs, faking flight fetches. No build step, no browser, no network. Runs in ~25 seconds.

## Run it

```bash
cd tests
npm install        # once; installs the pinned jsdom (see package.json)
npm test           # or: node run-all.js
```

`node_modules/` and the lockfile are git-ignored (repo convention) — the pinned version lives in `tests/package.json`. If jsdom ever needs bumping, bump it deliberately and re-run everything.

## Conventions (what keeps this evergreen)

1. **Assert outcomes, not internals.** "The share panel received the file", not "function X called function Y". Outcome tests survive refactors — the export logic was rewritten twice without touching these assertions.
2. **New features bring their test block.** The feature's "verify" step becomes a permanent suite block, added in the same sitting as the feature.
3. **Intentional behaviour changes update the matching block.** A failing test after a deliberate spec change is the net doing its job — re-sign the contract in the same commit. The cost stays proportional: minutes, never a rewrite.
4. **IDs are contracts.** The app's element ids (`btn-dev-save`, `ca-arch-trash`, …) are stable and pinned by the owner's specs; tests may rely on them. classNames only where the spec pins them (colours, pill styling).
5. **Date-anchored seeds.** Suites that depend on "today" (current-month expansion, partial-month projections, month badges) seed the real current calendar month and **compute date-derived expectations from the run date** — never hardcode the day. A calendar rollover fails them loudly on purpose: reseed the months and figures, never change app behaviour to match stale seeds. Two traps hotfix 9 added to this rule: seeds compared against a ROLLING window (the backup nudge's "newer than the last export") must derive from the run date, not fixed ones — a fixed date crosses the window overnight; and seeds built from bare `hh:mm` strings must carry the true `ymd`/`staYmd` of real moments — near midnight the strings straddle the day boundary and trip the app's overnight-arrival rule (a 02:17 SGT run caught both). The harness pins the box to Asia/Singapore (`process.env.TZ` at require time) because the app's naive wall math (expiry sweeps, day labels) and its zone-aware station math agree only on the crew's own clock — an unpinned box can split them (the 2026-10-03 UTC sandbox did, and exposed a real on-device date bug); the pin is why. v1.45.58 paid the rule at ship time: the box crossed into November mid-hotfix and every date-anchored block that booted WITHOUT a `now:` pin broke at midnight — the calendar's default month moved past the seeded October and the fixed-date cells fell out of the mounted grid (the real-October mega-block, the Jun-2025 PDF block, the week-wrap synthetic, the arrow-keys block; all four now pin their clock). A block that speaks a fixed date and reads the page's TODAY must pin `now:` — the rollover failure is loud on purpose, and the fix is the pin, never the app.
6. **Timing:** the harness boots jsdom and waits 400ms — jsdom fires its own `DOMContentLoaded` exactly once. **Never dispatch it manually**; double-firing double-binds every listener (a real bug this suite caught). Dialog close fades take 200ms — wait ≥400ms after OK/Cancel before asserting `hidden`.

8. **`w.eval` sees function declarations, not `let` bindings.** Top-level `let`/`const` in the app's scripts never become window properties — assert through functions (`rcTintKind(...)`, `rosterCalSelect(...)`) or the DOM, never by eval-ing a variable name (hotfix 10's first heal pin died on `rcTL is not defined`).
9. **Store-shape tests boot FRESH; shared-page mutations need the re-read trio.** The calendar caches legs per dkey (`rcLegCache`) and a same-day re-select is a render no-op — so mutating `localStorage` on a page that already rendered serves STALE legs and never re-renders the detail. For a store-shape pin (duty days without flights, a store-era gap), boot a new page (`await boot(APP, { seed })`) so the store is the only voice. If you must mutate a live page (the SN60 idiom), the trio is: raw `setItem` → `rosterCalTimelineInit()` → select a DIFFERENT day and back. And run suites directly (`node suite.test.js` from `tests/`) — `_harness.js` is a library; executing it does nothing. (v1.45.50 lessons, both paid for: the first era pin ran on the shared legend page and read cached legs from earlier blocks; the solo run "passed" with empty output.)
10. **A sabotage must be able to evict the row.**
12. **Metric pins verify against hand-computed values, and new CSS rides the ladder.** A stats feature's live pins seed a small store whose every total is computed BY HAND first (the two-year telemetry seed: 9 legs / 1d 16h / KUL ×2 / 388 · 4 …) — a wrong number in the app then fails loudly against arithmetic, not against another render. And the dev-ui type-ladder guard is part of the net: new components using off-rung sizes (9px, 10px, the banned 15px) fail the battery — pick rungs (11 micro / 14 / 20 / 24), don't invent sizes.
13. **Overlay-over-overlay pins follow the stack.** When a sheet opens above another sheet (v1.45.53's All Flight Stats over the passport), the pins name BOTH wraps and their z-order, the close-of-parent also closes the child, and the Escape closers list is asserted in STACK ORDER — the top sheet's entry sits above the page beneath it. A gate that opens an overlay is pinned by its opener call, never by accordion markup that no longer exists.

14. **Re-skins re-pin the SKIN, not just the markup.** When a surface changes clothes (v1.45.54's earnings re-skin), every computed-style pin on the old look is a failing pin: grep the suite for the retired values (the navy gradient, the gold numerals, the glider transform, the mono stack, the wash alphas) and re-point each to the new idiom — then ADD pins for the new vocabulary (the pair values, both themes) so the next drift trips a wire.

15. **Ladder surgery shifts EVERY rung below the insert — walk the whole ladder after.** When a release takes entries[0] of the E6 changelog ladder, every older rung's index moves down one. A partial shift (a range loop from n≥3 plus a separate text re-point for one rung) leaves a rung unshifted or duplicated beside the new head — v1.45.55 paid for it: the 1.45.52 rung stayed at [2] next to the re-pointed 1.45.53 and the suite failed 794/1. After ANY ladder edit, print every rung's version-versus-index ([0] newest … down to the floor) before running, and let the per-rung version pins be the net that catches what the eye missed. And a shift loop that matches "the first entries[N]" will sweep a rung you JUST inserted at that index — v1.45.56's loop crossed the new 1.45.55 pin with the 1.45.54 rung; the walk caught it before the suite ran. Insert the head, then shift, then swap-check the [1]/[2] pair explicitly.

16. **Animated values: text reads anytime, shape reads after the settle — and mid-roll reads are SYNCHRONOUS.** When a feature animates an element's content in place (v1.45.56's digit roll), pin the contract that makes it testable: the element's textContent is the settled truth even mid-animation (base text kept, decoration drawn elsewhere), so TEXT pins may read at any moment — but pins that read DOM SHAPE (children, innerHTML, styles of inner nodes) must wait out the animation's restore (~850ms for the roll). And a "the animation mounted" pin must read in the SAME task as the triggering tap, with no await between — an await can stretch past a short animation under box load (a wait(120) once read past a 570ms restore and "failed" a working roll). A restore that reinstates captured markup must capture the CURRENT state at roll time, never a first-roll snapshot — otherwise a second animation on the same element reverts the value when it settles (the smoke rig caught jsdom missing this: every jsdom render re-set the text before the roll, so the stale capture never showed). v1.45.57 paid the shape-wait a THIRD time, both rigs: every ctx-cell innerHTML read after a figure change (trend icons, projection spans, the bullseye milestone) needs the settle wait — text reads ride the truth mid-roll, shape reads do not; and a "the hidden quadrant never rolls" pin read right after the lens click sees the PREVIOUS roll's still-mounted cells (~300ms into the open's ~850ms restore) and fails — the never-rolls proof reads after the settle, ideally beside a src pin on the `:not(.hidden)` walk that IS the mechanism. And when a card rolls as ONE FAMILY on a whole-card fingerprint (v1.45.57's earnings card), pin the fingerprint forms themselves — the figs list, the `fv` join, the `_fv !== fv` gate, the forEach — because the family decision is the feature. And the E6 ladder's version-anchored shift carries its own trap, paid in v1.45.58: when the head insert WRITES the new [1] rung, the shift loop must not carry a case for that same version — the pattern matches the freshly-written rung and crosses the ladder (shift only the OLD rungs, one version past the new head). A changelog pointer containing a JS unicode escape is pinned with the backslash DOUBLED (the pin writes two backslash characters before the u-hex code, or JS resolves the character at parse time and the pin dies on the literal source bytes).

11. **Instant-behaviour pins read SYNCHRONOUSLY; absence pins quote the code form.** A "hides the moment the tap lands" claim is pinned by reading state in the SAME task as the click (`tagBtn.click(); R.ok(...)` with no `await wait` between) — any sleep can mask a replay window the old code left. And when a rename retires a UI string, pin the absence of its CODE forms (`aria-label="Your records"`, `>Your records</h3>`), never the bare phrase — the changelog pointer that announces the rename quotes it (the ek lesson, paid twice now: v1.45.49's comment, v1.45.51's pointer). The virtualized window renders ±6 rows of context, so scrolling a today near the timeline's start to the TOP cannot push its row out of the DOM — fling to the far bottom instead (hotfix 10).
