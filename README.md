**CrewAssist** is a Progressive Web App (PWA) for Singapore Airlines (SIA) cabin crew. It is a mobile-first, chatbot-style assistant for inflight and layover calculations, plus live digital inflight menus. It is an **unofficial** crew tool.

As of **v1.24.0** (`crewassist-v131`): chat, COP/IFA/LMA calculator (per-sector Fetch from flight number + date, trip bars, refetch gating, Default/Manual/Advanced interface modes), roster PDF import (multi-month stitching, Calculate all, Flight Overview, one-tap save-all), the **Earnings page** (Month / Year / All-time summary, a twelve-month chart with the current month projected to month end, twelve insight cards, Best/Low/In-progress badges and year-on-year arrows), inflight menu viewer + printer, a five-step feature tour, and a developer rates editor; offline last menu is **not built yet**. Next-agent instructions live in [`HANDOVER.md`](HANDOVER.md) (start with its **Cold start** section). Formulas live in [`LOGIC.md`](LOGIC.md). The SQ inflight-menu API map lives in [`API_REFERENCE.md`](API_REFERENCE.md). The feature tour's beat-by-beat script lives in [`TOUR-BREAKDOWN.md`](TOUR-BREAKDOWN.md); the test-suite contracts live in [`tests/README.md`](tests/README.md).

## Features & Goals
- **Chatbot interface:** NLP-style intent matching for quick commands (`menu`, `print`, `IFA`, `LMA`, `COP` / `total`). Jump-to-latest control matches the send button and only shows when the thread is not at the bottom. Typing dots play before every bot line, calculator, and menu lookup. After a bubble finishes entering, wait 500ms before the next bubble or typing. Send, chips, and in-chat buttons stay locked until that animation finishes (no spam). Welcome is two bubbles. Messages, cards, typing, and lookup blocks fade/slide in and out.
- **COP / IFA / LMA calculator:** Day-by-day engine for layover and turnaround allowances from `LOGIC.md`, with coefficients from `rates.json`. Any chat bubble **taller than the visible chat area** opens with its **top** on screen instead of scrolling past it; a shorter bubble still scrolls to the end of the thread (so a COP card, which is long, lands on its top); COP/IFA/LMA cards are **85%** like the inflight menu card. Flight and date share equal width on one row. Dates use a CrewAssist calendar (DD/MM/YYYY; cream panel in light, navy in dark; gold hairlines under the header date and between the legend and Today / Cancel / OK). Days outside today−2 … today+6 weeks are crossed out; COP can still pick them (Fetch then explains), inflight menu cannot. A calculator date field also cannot go before the sector or station above it — those days are crossed out and refuse the tap. Fetch keeps the typed date. Under the pills a **trip bar** shows the journey as IATA codes with arrows (`SIN → JNB → CPT → JNB → SIN`, `···` until a leg is fetched), each code in its own little card. The panel is **two rows**: the chips own the full top row and **never wrap** (`flex-nowrap`, so a route wider than the card scrolls sideways instead of dropping a chip), with `2 of 4 fetched`, Expand all and **Fetch all** on the row below — there are no longer per-sector Fetch buttons, and the button is sized to stay inside the chat bubble. Fetched cards fold and unfold with a smooth max-height/opacity animation. If the word `Turnaround` cannot fit its pill on a narrow card, it shortens to `Turn` (the value stays `Turnaround`); a wider card keeps the full word. The pills are `min-w-0 overflow-hidden` so the fit test measures a constrained pill, and it re-runs on resize, `load`, `document.fonts.ready` and a few post-render passes so a late webfont can't ship the wrong label. **Fetch all lights up exactly like Calculate** (`cta-gold`) once every flight number is filled, and goes inactive once the trip is complete; changing a flight number or a date brings it back. If any selected date is outside the live-data window it raises one window — *"Live flight information isn’t available for the selected dates."* — rather than one per sector. One tap fills every outstanding sector from `/api/sq` **strictly one after another**; a sector being fetched shows a pulsing gold dot that turns green on success, and only a failed sector gets its own **Retry** button. A fetched sector **folds to one row** (flight number, date, and the duration as **2h 15m** with a clock icon — not `02:15`, which reads as a time of day); tapping the row expands it again, and editing it marks it unfetched. The first sector that is not fetched yet always stays open, and an **Expand all** link appears once anything is folded. Below Calculate a line states the position: `Fetch all sectors to continue (2/4)` or `All sectors fetched · Ready`. Fetch fills hours and the adjacent LMA in/out; typing still works and Calculate does not require a flight number. Calculate **does** require a flight time on every sector, typed or fetched — in Default mode that field is hidden, so Fetch is how it lands. The trip bar and its hint are hidden in Manual mode, which is hand-entry only. The flight-number placeholder hints at the shape of the pairing: **SQ 632 / 633** on a 2-sector layover, **SQ 852 / 853** on a 2-sector turnaround, **SQ 12 / 12 / 11 / 11** on a 4-sector layover and **SQ 136 / 135 / 994 / 995** on a 4-sector turnaround. The hours field reads **Flight Time Duration (HH:MM)**. Sector dates use **the same cascading rule as the LMA dates**: sector 1 defaults to today, each sector below it to the day after, and changing any date rewrites every date below it to the day after the one above — in order, whether or not it was already in sequence. The sector you typed, and everything above it, is left alone. Multi-leg flights pick the unused sector. **Direct US** is a toggle row (flag icon, `ULR flight — 3.5×`) that Fetch ticks when a fetched sector is to or from the US; **Paxing** is a separate toggle row below it (armchair icon, `Deadheading — 0.75×`), and both multipliers are read live from `rates.json`. LMA (on COP and on the LMA calculator) gets the same trip bar treatment: `SIN → LHR → CDG` from the typed Station IATA codes, `1 of 3 fetched`, one **Fetch all** that walks each station's inbound then outbound leg in sequence, a status dot per station (gold pulsing → green, red on failure) and a **Retry** button only on a leg that failed. A station folds to `SQ 265 / 266  LHR` once both legs are in; editing it marks both legs unfetched again. Times can still be typed. Calculate waits for a **valid three-letter Station IATA** and **both times**, typed or fetched; a station with Shuttle ticked earns no LMA and is exempt. First Fetch on a 4-sector pairing does not jump the chat. The summary sheet opens scrolled to the top. LMA placeholders are station `e.g. BNE` and flight `SQ 265`. LMA stations are labelled **Arrival Date / Arrival Time / Departure Date / Departure Time**, with a **Shuttle** toggle row last, below Departure Time, and **only on the second layover station**. **Shuttle** zeros that layover only (not IFA Turnaround; not hardcoded flight numbers). Developer mode (10 taps): paired rank rates, SDP buffers, overrides & bonus, layover/turnaround bands, LMA meal windows, and LMA region B/L/D. Settings → **Allowance calculator interface** (one segmented pill, each option with its own icon, title and description; Default is marked ★ Recommended) chooses how much the calculator shows: **Default** — *Smart automation*, hides the IFA flight-time field, the Direct US toggle and the whole LMA Flight Details block on COP, because flight number + date lets Fetch fill them; **Manual** — *Full manual control*, hides Fetch all and both trip bars so flight and date share the row; **Advanced** — *Advanced breakdowns*, shows everything (pill appears only in developer mode, and turning developer mode off drops the mode back to Default). On the LMA-only calculator Default hides Station IATA and both time fields instead (it has no IFA section to hide). The choice is stored per device as `crewAssist.calcUi` and repaints calculator cards already in the thread. Hidden fields never block Calculate — but in Default the flight number becomes the required field, so Calculate stays greyed until it is entered. **Flight Type** and **Sector Count** are pill selectors (Layover and **2** picked by default; the count pills read just `2` and `4` so the whole row fits one line); picking a different one clears the card: IFA sectors are rebuilt and LMA stations reset to one empty station. Summary overlay: `formatMoney`; IFA sectors First–Fourth Sector (`(Paxing)` when that sector is paxing); LMA day cards (DD MMM YY) with aligned B/L/D badges.
- **Roster PDF import:** A paperclip beside the chat input (or typing `roster` / `upload` / `import`) attaches the monthly **Crew Roster Report PDF** and reads it entirely on-device — pdf.js loads from CDN on demand (same pattern as the image exporter); nothing is uploaded anywhere. Flight rows are reassembled from the rotated table by position (overnight flights merge with their landing-day echo rows) and chained into trips: same-day pairs become turnarounds, back-to-back same-day pairs merge into one 4-sector day, stops with more than 6h ground become layovers whose LMA stations and in/out times come from the roster's port-local STD/STA. A confirm bubble reports the month — trips · sectors · flying days, skipped non-flying days, flagged trips and why — and one-shot **Build** / **Discard** buttons decide. Build renders one folded calculator card per trip with flight numbers, flight times, dates (after-midnight departures dated on the flight, not the duty), LMA stations and the Direct US tick (2-sector layovers touching the US) prefilled through the calendar-commit path, so cascades, trip bars and Fetch-all re-arm behave as if the crew typed it. Fetch still works on every card and still never overwrites the dates. Attach two months together and a trip crossing the boundary (out on the 29th, back on the 2nd) builds complete — the reports are stitched into one timeline, and duplicate months in one pick are skipped with a note. **Calculate all** sits under Build/Discard: one tap builds and calculates every trip and shows one combined summary — grand total, per-trip breakdowns, a single Save that files them all — while Build + per-card Calculate remain for one-at-a-time checking. Every summary (single or combined) opens each trip with a **Flight Overview** — a plain-English, personal-voice rundown of the flight numbers, times, how IFA was derived, when you landed into and left each station, and what LMA covers — and every saved flight in the earnings archive is tappable to reopen its full summary exactly as it was calculated that day. Unreadable times, trips that do not return to SIN by month-end, >4-sector loops and non-roster PDFs are reported honestly — never guessed.
- **Feature tour:** a five-step demonstrative walkthrough — chat basics; the roster showpiece, where a synthetic demo month runs the real pipeline (Calculate all, save, the earnings archive, tap-through); Default calculating, fetch-driven; Manual calculating, switched through the real Settings pill and typed by hand; and menu, the two ways to ask for what's being served — chat bar and chip lit alternately before the Finish. Offered once on first run after the greeting, or start it any time by typing `tour` (or `help`); skippable at every step, paced by Next-button reading pauses between the chapters; while it runs the chrome is hands-off (no scrolling, no Settings, no clear-chat, no chips), and it ends by clearing the chat to a clean thank-you. A gold ring pulses on whatever the narration names. Demo saves live in a session store and the whole demo thread folds away at the end — the crew's own data is never touched and their calculator mode is restored. Steps are data (a registry of self-contained step objects), so future features slot into the tour without touching the engine, and a step whose target has disappeared skips itself instead of breaking the run.
- **Inflight menu viewer:** Live JSON from SQ `getcabin` / `menu` via the Vercel proxy (`/api/sq`). Chat card titled Inflight Menu; last five successful lookups as horizontally scrolling chips (right mask, same as chat chips). Fetch menu uses a book icon for viewing and a printer icon for print. Overlay keeps the selected sector when switching cabin. After Fetch menu, the bot says “Fetching menu from seat pocket” then “Here is the menu”. Overlay: route hero, cabin / sector / cuisine dropdowns, segmented Meals · Drinks · Snacks · Amenities bar, centered meal-service tabs, editorial course cards, drinks/snacks hairlines, Delectables/snacks as bullets. Dish photos: linked `imagePathIfeHigh` when SQ sends it, otherwise constructed from dish `id` on the inflightmenu CDN; same-name dishes reuse a working photo/id across sectors, cabins, and later fetches (no name hardcoding). Missing CDN → gold bullet. Amenities as bullets. More/Less on long copy.
- **Inflight menu printer:** Same slide-up glass overlay as the menu viewer. Switch View ↔ Print from the sheet headers (book / printer) using the current flight — no second lookup. Numbered sector sheets (`1 LAX → NRT`). Toolbar pills match Menu sheet / Edit content size. Elegant auto-selects A4, Compact auto-selects A6 (size chips stay toggleable after). Preview is a real A4/A6 page scaled to the overlay width. Sector / Elegant-Compact / A4-A6 jump the preview to the top. Snacks except Light Bites, and drinks except Champagne / red / white wine, start hidden (Show in Edit). Compact also hides bakery / hot drinks, SCL Chocolate plus Cheese and Crackers, and YCL Cheese and Crackers. Menu sheet and Edit content scroll independently. Edit content uses collapsed, animated cabin accordions. A−/A+ grey out at 70% / 140%. Elegant pills are Bounds, then Descriptions, then Greyscale. Export PNG / JPEG / Word at high quality (compact is drawn at 300 dpi so protein invert sits on the text baseline; elegant html2canvas uses scale 3). Compact uses a per-service header with the date after the meal (`SQ478 (→JNB) JCL (SUPPER) 160926`) and a full-width rule after each service (including the last; none above the first). A Bounds pill draws the A4/A6 page edge on the preview only (never in the export). Printer loading copy is “Preparing the menu”.
- **Design system:** SIA Navy, Charcoal, and Gold; glassmorphic bubbles and bottom sheets; animated starry sky; iOS-first layout. Icons are Lucide throughout — there is no emoji in the app.

## Tech Stack
- **Frontend:** HTML5, CSS3, vanilla JavaScript, Tailwind CSS (CDN), Lucide Icons. Almost all UI and logic is a single `index.html`.
- **Backend / proxy:** Node.js Vercel serverless function (`api/sq.js`) for `getcabin` and `menu` only. SQ CORS allowlists `inflightmenu.singaporeair.com`, so the browser cannot read JSON directly; images are plain `<img src>` to that host (not CORS-gated).
- **Data:** Airport IATA list and regions inlined in `index.html`. Default IFA/LMA numbers in `rates.json`. SQ payload and image URL map in `API_REFERENCE.md`. Formulas in `LOGIC.md`.
- **Architecture:** PWA (service worker `crewassist-v131`, web manifest) for install and cache. App SemVer `APP_VERSION` (currently 1.24.0) is shown on onboarding. A What’s new overlay lists `APP_WHAT_NEW` after onboarding (or on the chat page for returning crew). Close with the X; “Do not show again” sits **outside** the glass window, checkbox and label on one row, and stores `crewAssist.hideWhatsNew` for this stamp only. IFA/LMA numbers and meal windows load from `rates.json` (network-first); developer mode can save device overrides and export/import JSON. Publishing new rates to every install is replacing `rates.json` on GitHub (not from the PWA).

## File Structure
- `index.html` — UI, chat, calculators, menu overlay, printer, and all app logic.
- `manifest.json` & `sw.js` — PWA install and cache (`crewassist-v86`).
- `rates.json` — Default IFA modifiers and LMA region rates (fetched network-first).
- `api/sq.js` — JSON proxy to SQ `POST …/api/getcabin` and `…/api/menu` (avoids CORS / WAF issues).
- `API_REFERENCE.md` — Reverse-engineered SQ inflight-menu API: endpoints, payload tree, image fields, dish-id CDN URLs, CORS.
- `LOGIC.md` — Source of truth for COP / IFA / LMA formulas and rules.
- `icons/` — Transparent dart for in-app (`logo-192.png`, `logo-512.png`); navy + gold PWA icons (`app-icon-180/192/512.png`).
- `README.md` — Overview, stack, setup, and tree.
- `HANDOVER.md` — AI-agent handoff: current build, open work, and constraints.
- `tests/` — jsdom behaviour tests for the shipped features (`cd tests && npm install && npm test`; see `tests/README.md`).

## Setup & Running
1. Clone the repository.
2. Frontend only: serve the root (e.g. `npx http-server` or `python3 -m http.server`).
3. Proxy / live menus: Vercel CLI (`npm i -g vercel`) then `vercel dev`.
4. Use a mobile viewport (or a phone) — the UI is built mobile-first.

Install as a PWA from the phone browser. After a deploy, confirm the onboarding stamp matches `APP_VERSION` (currently `v1.19.22`). Onboarding title: hairline the width of `CrewAssist™`, then `AN UNOFFICIAL CREW TOOL` on one row, same colour as the SemVer stamp.

## Tests
`tests/` holds the jsdom behaviour suite: it boots the real `index.html` in a fake browser and asserts the feature contracts (rates editor state machine, exports across PC/iOS/Android, archive behaviour, trip bars, dev UI, roster PDF import). Run with `cd tests && npm install && npm test` — no build step, ~25s. New features bring their test block; intentional behaviour changes update the matching block in the same sitting. Details and conventions: `tests/README.md`.
