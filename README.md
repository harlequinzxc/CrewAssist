**CrewAssist** is a Progressive Web App (PWA) for Singapore Airlines (SIA) cabin crew. It is a mobile-first, chatbot-style assistant for inflight and layover allowance calculations, roster reading, and live digital inflight menus. It is an **unofficial** crew tool.

As of **v1.40.0** (`crewassist-v197`): a chat assistant with natural commands, the COP/IFA/LMA allowance calculator (Default / Manual / Advanced interface modes, rules verified against the Staff Members' Agreement), roster-PDF import with one-tap Calculate-all, the **Earnings page** (Month / Year / All-time summaries, a twelve-month chart with projection, twelve insight cards), a roster calendar, live inflight menu viewer + print sheet, an offline menu archive, a five-step feature tour, and a developer rates editor. Next-agent instructions live in [`docs/HANDOVER.md`](docs/HANDOVER.md) (start with its **Cold start** section). Formulas live in [`docs/LOGIC.md`](docs/LOGIC.md). The SQ inflight-menu API map lives in [`docs/API_REFERENCE.md`](docs/API_REFERENCE.md). The feature tour's beat-by-beat script lives in [`docs/TOUR-BREAKDOWN.md`](docs/TOUR-BREAKDOWN.md); the test-suite contracts live in [`tests/README.md`](tests/README.md).

## Features & Goals
- **Chatbot interface:** NLP-style intent matching for quick commands (`menu`, `print`, `IFA`, `LMA`, `COP` / `total`) plus natural commands (`cop sq802 6 oct sq807 8 oct`). Jump-to-latest control only shows when the thread is scrolled up. Typing dots play before every bot line; messages, cards and lookups animate in and out, and inputs stay locked while an animation runs.
- **COP / IFA / LMA calculator:** day-by-day engine for layover and turnaround allowances from `docs/LOGIC.md`, with coefficients from `rates.json`. Per-sector **Fetch** from flight number + date fills times, Direct US and the adjacent LMA in/out; a **trip bar** tracks the journey (`SIN → JNB → CPT → JNB → SIN`) with per-leg status dots, **Fetch all** walking every outstanding sector in sequence, folding fetched rows and per-leg Retry on failure. Dates cascade (sector 1 today, each next the day after) through a CrewAssist calendar. **Direct US** (3.5×) and **Paxing** (0.75×) are toggle rows read live from `rates.json`; a station with **Shuttle** ticked earns no LMA. Turnarounds with an overseas transit of **3 hours or more** (arrival to report time) earn location meals under Clause 36(4), and meal windows close at **report time** — an hour before departure (Clause 36(3)). Settings → **Allowance calculator interface** picks Default (smart automation), Manual (full hand-entry) or Advanced (everything; developer mode only). Summaries open with a plain-English **Flight Overview** and full IFA/LMA breakdowns.
- **Roster PDF import:** a paperclip beside the chat input attaches the monthly **Crew Roster Report PDF** and reads it entirely on-device (pdf.js from CDN, nothing uploaded). Flight rows are reassembled from the rotated table, chained into trips (same-day pairs → turnarounds, back-to-back pairs → one 4-sector day, >6h ground → layovers with prefilled LMA stations), and a confirm bubble reports the month before one-shot **Build** / **Discard**. Build renders one folded calculator card per trip, prefilled as if the crew typed it. Multi-month attachments stitch across boundaries. **Calculate all** builds and calculates every trip into one combined summary with a single Save. Unreadable times, non-returning trips, >4-sector loops and non-roster PDFs are reported honestly — never guessed.
- **Roster calendar:** a month grid of duty pills (flight, standby, course, layover, leave tints; one seamless capsule per multi-day run), today accent bar, tap-to-select with a detail timeline, month navigation bounded by the data, and every duty tappable into its saved earnings summary or a live-priced one.
- **Earnings archive:** saved flights grouped by month with totals, averages, on-track projection and vs-last-year context; a twelve-month chart with the partial month projected and hatched; Best / Low / In-progress badges; twelve insight cards (streaks, breaks, nights away, busiest weekday); search and per-entry delete with undo. Tapping a saved flight reopens the full summary exactly as it was calculated that day; old entries say so honestly.
- **Feature tour:** a five-step walkthrough (chat basics; the roster showpiece with a synthetic demo month; Default calculating; Manual calculating; menus), offered once on first run or via `tour` / `help`, skippable at every step, paced by Next-button pauses, hands-off chrome while it runs, ending with a clean thank-you. Demo saves live in a session store — the crew's own data is never touched.
- **Inflight menu viewer:** live JSON from SQ `getcabin` / `menu` via the Vercel proxy (`/api/sq`). Route hero, cabin / sector / cuisine dropdowns, Meals · Drinks · Snacks · Amenities bar, editorial course cards; dish photos from SQ's image fields or constructed from the dish id on the inflightmenu CDN, with working photo/id reuse across fetches. Missing CDN → gold bullet.
- **Inflight menu printer:** the same overlay with View ↔ Print on the current flight. Elegant / Compact presets (A4 / A6), a real page-scaled preview, per-service headers with dates, content-size editing with cabin accordions, and PNG / JPEG / Word export at high quality.
- **Offline menu archive:** the schedule reader keeps the last successful menus viewable offline (with an honest offline badge), prunes stale entries, and nudges when the local backup ages out.
- **Design system:** SIA Navy, Charcoal and Gold; glassmorphic bubbles and bottom sheets; animated starry sky; iOS-first layout. Icons are Lucide throughout — there is no emoji in the app.

## Tech Stack
- **Frontend:** HTML5, CSS3, vanilla JavaScript. Almost all UI and logic is a single `index.html`. Tailwind ships as a **compiled stylesheet** (`tw.css`, rebuilt from `tw.config.cjs` — no CDN runtime); Lucide icons.
- **Backend / proxy:** Node.js Vercel serverless function (`api/sq.js`) for `getcabin` and `menu` only. SQ CORS allowlists `inflightmenu.singaporeair.com`, so the browser cannot read JSON directly; images are plain `<img src>` to that host (not CORS-gated).
- **Data:** Airport IATA list and regions inlined in `index.html`. Default IFA/LMA numbers in `rates.json` (network-first; developer mode can save device overrides and export/import JSON). SQ payload and image URL map in `docs/API_REFERENCE.md`. Formulas in `docs/LOGIC.md`.
- **Architecture:** PWA (service worker, web manifest) for install and cache; the worker precaches the shell, `rates.json` and the CDN runtime deps with retries, and runs network-first for documents and rates. App SemVer `APP_VERSION` (currently **1.40.0**) shows on onboarding. `APP_CHANGELOG` (v1.0.0 → current, newest first) drives both the What's New overlay (the unseen delta, stamped `crewAssist.wnSeen`) and Settings → Changelog.

## File Structure
- `index.html` — UI, chat, calculators, roster import, calendar, earnings, menu overlay, printer, and all app logic.
- `manifest.json` & `sw.js` — PWA install and cache (`crewassist-v197`).
- `tw.css` & `tw.config.cjs` — the compiled Tailwind stylesheet and the config that rebuilds it (rebuild when class names change; the CLI lives in `tests/smoke/node_modules`).
- `rates.json` — default IFA modifiers and LMA region rates (fetched network-first).
- `api/sq.js` — JSON proxy to SQ `POST …/api/getcabin` and `…/api/menu` (avoids CORS / WAF issues).
- `icons/` — transparent dart for in-app (`logo-192.png`, `logo-512.png`); navy + gold PWA icons (`app-icon-180/192/512.png`).
- `docs/` — all written matter: `LOGIC.md` (formulas), `HANDOVER.md` (agent handoff), `API_REFERENCE.md` (SQ API), `TOUR-BREAKDOWN.md` (tour script), `_reference_rosters/` (the owner's real roster/menu PDFs the regression suite reads), and the full Staff Members' Agreement (`CA_058_of_2025_Singapore_Airlines_Staff_Members_Agreement.pdf` — Clauses 34–36 are the ones this app implements).
- `tests/` — the jsdom behaviour suite plus `tests/smoke/`, the real-Chromium browser rig (`cd tests && npm install && npm test`; see `tests/README.md`).
- `README.md` — this overview.

## Setup & Running
1. Clone the repository.
2. Frontend only: serve the root (e.g. `npx http-server` or `python3 -m http.server`).
3. Proxy / live menus: Vercel CLI (`npm i -g vercel`) then `vercel dev`.
4. Use a mobile viewport (or a phone) — the UI is built mobile-first.

Install as a PWA from the phone browser. After a deploy, confirm the onboarding stamp matches `APP_VERSION` (currently `v1.40.0`) — a mismatch means cache, not code.

## Tests
`tests/` holds the jsdom behaviour suite: it boots the real `index.html` in a fake browser and asserts the feature contracts (12 suites, ~1,800 checks). `tests/smoke/` is the real-browser layer — it boots the app in actual Chromium and checks boot health, release stamps, What's New and the headline calculation semantics. Run the jsdom suite with `cd tests && npm install && npm test` (~25 s) and the smoke with `cd tests/smoke && npm install && node run.js`. The real-roster regression tests read every PDF in `docs/_reference_rosters/`, so a fresh clone runs the full suite out of the box. New features bring their test block; intentional behaviour changes update the matching block in the same sitting. Details and conventions: `tests/README.md`.
